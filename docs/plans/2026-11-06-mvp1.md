# План разработки: справочник «Как стать AI Engineer», MVP 1.0

> **Статус:** согласован 2026-11-06, в работе.

**Цель.** Офлайн-справочник и учебник по профессии AI Engineer в одном HTML-файле. Он открывается двойным кликом, а пополняется через ИИ по правилам из AGENTS.md.

**Архитектура.** Повторяем схему spanish-grammar: один файл `ai-engineer.html` (разметка, CSS, данные, JS), валидатор на Node, AGENTS.md с правилами, git с пушем в `main` репозитория `maart/ai-engineer`. Без сборщика и зависимостей.

**Читатель.** PL/SQL-разработчик без опыта в Python и ML. Поэтому блок «Фундамент ПО» начинается с Python с нуля, у тем есть необязательное поле `fromSql` («как это выглядит для SQL-разработчика»: аналогии и отличия), а темы, где знание БД даёт фору (эмбеддинги в pgvector, хранилища, пайплайны данных), отмечены отдельно.

**Три языка.** Весь контент и интерфейс на русском (по умолчанию), английском и испанском, переключатель языка в шапке, выбор запоминается. Каждое текстовое поле хранится как `{ ru, en, es }`; валидатор не пропускает тему, где нет хотя бы одного языка. Код в примерах общий. В глоссарии термин показывается на всех трёх языках сразу, чтобы учить лексику для собеседований. Поиск идёт по текущему языку и по английским терминам.

**Источник контента.** Документ «Карта навыков AI-инженера (2026)»: 9 блоков и таблица приоритетов.

## Структура репозитория

```
ai-engineer/
├── ai-engineer.html     ← всё приложение
├── validate.js          ← проверка данных и кода: node validate.js → RESULT: PASS
├── AGENTS.md            ← правила для ИИ: как добавлять темы, что обновлять
├── README.md
├── LICENSE              ← MIT, как в spanish-grammar
├── .gitignore
└── docs/plans/          ← планы разработки (этот файл)
```

## Модель данных (внутри HTML)

- **BLOCKS:** `id`, название, порядок, краткое описание. Девять блоков: фундамент ПО, LLM, API, RAG, агенты и MCP, evals, продакшн, ML и fine-tuning, soft skills.
- **TOPICS:** `id`, `block`, название, приоритет (обязательно / желательно / плюс, по таблице приоритетов), «что это», «зачем», понятия (ссылки на глоссарий), пример (код или схема), ресурсы (`title`, `url`, тип, язык), мини-задание, `fromSql` (необязательно), `prereq` (на какие темы опирается), `related`, **`checked`** (дата последней проверки актуальности).
- **GLOSSARY:** `id`, термин (англ.), перевод, определение, темы.
- **CHANGELOG:** дата, заголовок, текст, связанные темы, источник.

**Состояние пользователя** (localStorage): статус темы (не начато / изучаю / понял / применил), заметки к теме, «Входящие» (быстрые ссылки и мысли). Есть экспорт и импорт в JSON, чтобы прогресс не потерялся при очистке браузера.

## Интерфейс

- **Шапка:** название, общий прогресс по темам, поиск по всему тексту (темы, глоссарий, лента), переключатель темы оформления.
- **Вкладки:** «Карта» (блоки и темы), «Глоссарий», «Лента изменений», «Мой прогресс» (статистика, входящие, экспорт и импорт).
- **Карта:** слева блоки с темами и значками статуса, справа карточка темы. Фильтры: по статусу, по приоритету, «требуют проверки».
- **Свежесть:** если `checked` старше 120 дней, у темы появляется метка «проверить актуальность».
- **Адреса:** `#topic-<id>`, `#term-<id>`, чтобы ссылаться на конкретную тему.
- **Футер:** версия MVP и дата обновления.

## Этапы

Каждый этап заканчивается прогоном `node validate.js` с `RESULT: PASS`, коммитом и пушем в `main`.

### Этап 0. Скелет репозитория (MVP 0.1)
- [x] README, AGENTS.md, LICENSE, .gitignore, пустой `ai-engineer.html` с футером, `validate.js`, который извлекает `<script>` и запускает проверки.

### Этап 1. Модель данных и валидатор (MVP 0.2)
- [x] Структуры BLOCKS / TOPICS / GLOSSARY / CHANGELOG и 2–3 тестовые темы.
- [x] Проверки: каждое текстовое поле на ru/en/es, все строки интерфейса на трёх языках, уникальные id, все ссылки (`block`, `prereq`, `related`, понятия, темы в ленте) существуют, обязательные поля заполнены, даты в формате ГГГГ-ММ-ДД, URL только https, нет циклов в `prereq`.

### Этап 2. Интерфейс карты (MVP 0.3)
- [x] Переключатель языка (ru/en/es, сохраняется, `lang` у `<html>`), навигация по блокам, карточка темы, адреса `#topic-…`, светлая и тёмная тема, мобильная вёрстка.
- [x] Поиск по темам и глоссарию.

### Этап 3. Прогресс и заметки (MVP 0.4)
- [x] Статусы, заметки, «Входящие», общий прогресс в шапке, экспорт и импорт JSON с нормализацией при чтении.

### Этап 4. Глоссарий, лента, свежесть (MVP 0.5)
- [ ] Вкладки «Глоссарий» и «Лента изменений», метки и фильтр «требуют проверки».

### Этап 5. Контент (MVP 0.6–0.9)
- [ ] По одному блоку за коммит: все темы из карты навыков, примерно 5–8 тем на блок. Ресурсы проверяются по ссылке, у каждой темы ставится `checked`.
- [ ] Глоссарий из понятий всех тем, первые записи ленты (состояние индустрии на ноябрь 2026).

- [ ] Независимое ревью кода, исправления, MVP 1.0.
